# Deploying

Two pieces:

| Piece | Where | What it is |
|---|---|---|
| Scanner (repo root) | AWS Lambda, container image, Function URL with response streaming | Headless Chromium + axe-core. `POST /api/scan` streams progress as newline-delimited JSON. |
| Frontend (`web/`) | Vercel | Next.js app. Calls the Lambda Function URL straight from the browser. |

```
Browser ──POST /api/scan──▶ Lambda Function URL (RESPONSE_STREAM)
   ▲                              │  status / page-preview / page-complete / report / done
   └──────── NDJSON stream ◀──────┘
```

## 1. Scanner → AWS Lambda

Needs: Docker, AWS CLI with credentials, and AWS SAM CLI (`brew install aws-sam-cli`).

```bash
# from the repo root
sam build
sam deploy --guided \
  --parameter-overrides AllowedOrigin=https://YOUR-APP.vercel.app
```

On the first `--guided` run, accept "create managed ECR repository" and let SAM save the answers to `samconfig.toml`. After that, `sam build && sam deploy` is enough.

The `ScannerUrl` output is your Function URL. Check it:

```bash
curl https://xxxx.lambda-url.REGION.on.aws/health
# {"success":true,"status":"ok"}
```

What `template.yaml` sets up:
- **arm64**, 3008 MB, 15-minute timeout, 1 GB `/tmp` (Chromium unpacks there).
- A Function URL with `InvokeMode: RESPONSE_STREAM` so progress reaches the browser live.
- CORS on the Function URL, limited to `AllowedOrigin`. Lambda answers the preflight itself.

**Building on an Intel machine?** Either change `Architectures` to `[x86_64]` in `template.yaml`, or keep arm64 and make sure Docker can build `linux/arm64` (Docker Desktop can).

**Chromium version:** `Dockerfile.lambda` pins `@sparticuz/chromium@152.0.0` to match Puppeteer 25 (Chrome 150). If you upgrade Puppeteer, bump it to the matching major.

### Costs and abuse

The Function URL is public (`AuthType: NONE`), and CORS only stops other websites, not scripts. Every scan runs Chromium for 20 seconds to a few minutes. Before you share the link widely:
- Set a **reserved concurrency** (e.g. 5) on the function so a flood can't run up the bill.
- Set an **AWS Budget** alert.
- If you need more, put the Function URL behind CloudFront + AWS WAF rate limiting.

## 2. Frontend → Vercel

```bash
cd web
vercel            # first run links the project; pick "web" as the root directory
vercel env add NEXT_PUBLIC_SCANNER_URL production   # paste the Lambda Function URL
vercel --prod
```

Or in the Vercel dashboard: import the repo, set **Root Directory = `web`**, add `NEXT_PUBLIC_SCANNER_URL`, deploy.

Then set the scanner's `AllowedOrigin` to the final Vercel domain and run `sam deploy` again.

## Local development

```bash
# terminal 1: scanner on :4000
npm install
npm run dev

# terminal 2: frontend on :3000
cd web
cp .env.example .env.local
npm install
npm run dev
```

Open http://localhost:3000.

## Sites behind Cloudflare / bot protection

The scanner uses a real Chromium with realistic browser settings and waits up to `BOT_CHALLENGE_TIMEOUT_MS` (20s) for Cloudflare's automatic "checking your browser" step to pass. Many sites pass. Sites that require an interactive "verify you are human" check, or that block AWS IP ranges, will still be blocked. For those, the frontend shows a one-line snippet that runs the same audit in the user's own browser, where they've already passed the check. The report downloads locally.

That script is `web/public/a11y-scan.js`. It's generated by `npm run build:standalone` (repo root). Re-run that after changing rules or the report template.
